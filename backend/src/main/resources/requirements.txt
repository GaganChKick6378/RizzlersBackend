    - Define cleaning task types with required times (e.g., immediate checkout cleaning, daily cleanup).
    - Generate tasks daily based on room statuses and variable check-in/check-out times.
    - Support multiple shifts (e.g., morning, afternoon, evening).
    - Prioritize tasks based on urgency and time windows (e.g., immediate cleaning before check-in is high priority).
    - Optimize staff allocation using linear programming with the OjAlgo library.
    - Handle staff absences (e.g., sick leave applied one day in advance) and alert the admin if there’s a staff shortfall.
3. **Task Types and Characteristics**
    - **Immediate Checkout Cleaning**:
        - For rooms checking out and checking in on the same day.
        - Time window: Between checkout time and check-in time.
        - Priority: High (must be completed before new guests arrive).
    - **Delayed Checkout Cleaning**:
        - For rooms checking out but not checking in on the same day.
        - Time window: After checkout time until the end of the last shift.
        - Priority: Medium (less urgent, can be scheduled later).
    - **Early Daily Cleanup**:
        - For rooms that are vacant but checking in today.
        - Time window: From the start of the first shift until check-in time.
        - Priority: High (rooms must be ready for arriving guests).
    - **Daily Cleanup**:
        - For occupied rooms requiring regular cleaning.
        - Time window: From the start of the first shift to the end of the last shift.
        - Priority: Low (flexible scheduling).

    - Fetch room statuses, staff availability, and shift details from the database.
    - Generate tasks based on the task types and room conditions.
    - Assign staff to their preferred shifts, respecting absences.
    - Use linear programming to allocate tasks to staff, ensuring:
        - No overlapping tasks for any staff member.
        - Tasks are completed within their time windows and staff shift durations.
        - High-priority tasks are assigned first (via weighted objectives in the LP model).

        - Calculate the total unassigned task time (in minutes).

6. **Time Management**
    - All times (e.g., check-in, check-out, shift start/end) should be interpreted in the property’s timezone.
    - Discretize time into 30-minute slots for the linear programming model to simplify task scheduling.
7. **Assumptions and Simplifications**
    - For this implementation, assume a single property. However, design the system to be extensible for multiple properties (e.g., filter data by property_id if available).
    - Skill levels of staff can be ignored for now but included as a future enhancement (e.g., assigning complex tasks to expert staff).

### Data Models

Define or adapt the following data models as Java classes to support the housekeeping service. These should align with or extend the existing database schema:

- **Room**
    - Fields: roomId (int), checkOutDate (LocalDateTime), checkInDate (LocalDateTime).
    - Purpose: Stores room details and booking status.
- **Staff**
    - Fields: staffId (int), preferredShiftId (int), skillLevel (int, optional).
    - Purpose: Tracks staff availability and preferences.
- **Shift**
    - Fields: shiftId (int), startTime (LocalTime), endTime (LocalTime).
    - Purpose: Defines available working shifts (e.g., 6:00 AM–2:00 PM).
- **TaskType**
    - Fields: taskTypeId (int), typeName (String), requiredTimeMinutes (int).
    - Purpose: Specifies cleaning task types and their durations.
- **Task**
    - Fields: taskId (int), roomId (int), taskType (TaskType), durationMinutes (int), windowStart (LocalTime), windowEnd (LocalTime).
    - Purpose: Represents individual cleaning tasks with time constraints.

### Implementation Steps

1. **Set Up Data Models**
    - Create Java classes for Room, Staff, Shift, TaskType, and Task if they don’t already exist in the hotel booking system.
    - Ensure these classes map to the existing database tables or new tables you’ll add.
2. **Repository Layer**
    - Define repository interfaces (e.g., RoomRepository, StaffRepository, TaskRepository) to fetch data from the database.
    - Implement these interfaces to connect to your existing database schema, adapting table names as needed (e.g., rooms, staff, clean_tasks).
3. **Task Generation**
    - Create a TaskGenerator class that:
        - Queries room statuses and booking data daily at 6:00 AM.
        - Generates tasks based on the defined task types and their time windows.
        - Uses the TaskType table to set task durations.
4. **Linear Programming Model**
    - Use the OjAlgo library to build an LP model:
        - **Variables**: Binary decision variables for each staff-task-start-time combination (e.g., x[staff][task][time] = 1 if assigned, 0 otherwise).
        - **Constraints**:
            - Each task is assigned to at most one staff member.
            - Staff cannot have overlapping tasks (check time slots).
            - Tasks must start within their windowStart and windowEnd and finish within the staff’s shift.
        - **Objective**: Maximize the number of assigned tasks, with higher weights for high-priority tasks (e.g., Immediate Checkout Cleaning = 10, Daily Cleanup = 1).
    - Solve the model to get the optimal task assignments.
5. **Housekeeping Service**
    - Implement a HousekeepingService class to orchestrate the process:
        - Fetch data via repositories.
        - Generate tasks using TaskGenerator.
        - Run the LP model to assign tasks.
        - Handle unassigned tasks by calculating shortfalls and generating admin alerts.
6. **Database Integration**
    - After solving the LP model, insert assigned tasks into the clean_tasks table with details like taskId, roomId, staffId, startTime, and endTime.
7. **Error Handling and Edge Cases**
    - Handle staff absences by excluding unavailable staff from the scheduling process.
    - If no staff are available for a shift, log an error and notify the admin.
    - Ensure the system gracefully handles missing or invalid data (e.g., null check-in dates).
